# Saturn Mailchat

**Saturn Studio · نسخه 1.0.0.0.0**

رابط فعلی یک وب‌اپ فارسی راست‌چین و واکنش‌گراست. این مخزن همچنین شامل طرح دیتابیس Supabase، سیاست‌های دسترسی و فایل‌های پایه‌ی PWA است.

## اجرای نسخه فعلی
- برای تست محلی، `index.html` را با یک وب‌سرور استاتیک اجرا کنید.
- برای انتشار، در GitHub به Settings → Pages بروید، گزینه Deploy from a branch را انتخاب کنید، شاخه `main` و پوشه `/(root)` را ذخیره کنید.
- پس از انتشار، سایت از آدرس GitHub Pages مخزن در دسترس خواهد بود.

## آنچه اکنون در رابط کاربری کار می‌کند
- رابط فارسی، راست‌چین و واکنش‌گرا
- ورود محلی با نام نمایشی (بدون احراز هویت سروری)
- ایجاد گفتگو و ارسال پیام آزمایشی در همان مرورگر
- ذخیره محلی گفتگوها در localStorage
- بخش‌های اولیه استوری، فروشگاه و تنظیمات
- تغییر ظاهر روشن/تیره
- manifest و service worker برای نصب‌پذیری و cache پوسته‌ی برنامه

## زیرساخت backend آماده‌شده
- `supabase/schema.sql`: جداول پروفایل، گفتگو، اعضا، پیام‌ها، استوری، محصولات و سفارش‌ها
- سیاست‌های Row Level Security برای محدودسازی دسترسی کاربران
- bucket خصوصی `saturn-media` با سیاست‌های پایه‌ی فایل
- فعال‌سازی Realtime برای جدول پیام‌ها
- `supabase/config.example.js`: الگوی تنظیمات عمومی کلاینت
- `supabase/SETUP.md`: مراحل ساخت و پیکربندی پروژه

## کارهای لازم برای نسخه آنلاین واقعی
**توجه:** صرف اضافه‌شدن schema به معنی اتصال رابط کاربری نیست. رابط فعلی هنوز localStorage را به کار می‌برد و پیام‌ها بین کاربران/دستگاه‌ها همگام نمی‌شوند. برای تبدیل آن به سرویس واقعی باید:
1. یک پروژه Supabase بسازید و SQL موجود را اجرا کنید.
2. فایل `supabase/config.example.js` را به `supabase/config.js` کپی کرده و URL و کلید عمومی پروژه را وارد کنید. فایل واقعی config در Git ignore شده است.
3. لایه‌ی client برنامه را به Auth، جداول، Realtime و Storage متصل و جریان‌های ورود/ثبت‌نام و مدیریت خطا را تکمیل کنید.
4. برای تماس صوتی/تصویری WebRTC به signaling و TURN نیاز است.
5. برای اعلان push، پرداخت، تأیید سفارش، پنل مدیریت و عملیات حساس، backend امن و webhook سمت سرور لازم است.

## امنیت
- کلید `service_role`، رمز دیتابیس، کد ادمین و کلید درگاه پرداخت را هرگز در فایل‌های عمومی یا JavaScript مرورگر قرار ندهید.
- RLS را خاموش نکنید و تغییر وضعیت سفارش به `paid` را فقط پس از تأیید webhook معتبر انجام دهید.
- پیش از عرضه عمومی، محدودیت نرخ، گزارش/مسدودسازی، حذف حساب، سیاست حریم خصوصی و تست امنیتی لازم است.

**وضعیت:** پوسته و نمونه محلی قابل اجراست؛ backend schema آماده‌ی پیکربندی است، اما یکپارچه‌سازی کامل backend و قابلیت‌های وابسته به سرویس خارجی هنوز انجام نشده‌اند.
